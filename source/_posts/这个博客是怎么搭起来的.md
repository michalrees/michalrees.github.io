这个博客用 **Hexo 8 + Butterfly 主题** 生成，托管在 **GitHub Pages**，发布由 **GitHub Actions** 自动完成。下面是完整的搭建过程和踩过的坑。

## 选型

| 决定 | 选择 | 理由 |
|---|---|---|
| 框架 | Hexo | 中文生态最全，主题多，用 Node 写 |
| 主题 | Butterfly | 卡片式、功能全、暗色模式、自带本地搜索 |
| 托管 | GitHub Pages | 免费、自动 HTTPS、和仓库无缝集成 |
| 发布 | GitHub Actions | 推送即上线，本地不用装环境 |

## 关键坑一：Pages 把 Hexo 源码当 Jekyll 建

一开始用最常见的做法——把源码推到 `main`，Pages 设置成从 `main / (root)` 发布。构建直接失败：

```
Theme: butterfly
Error: The butterfly theme could not be found. (Jekyll::Errors::MissingDependencyException)
```

原因是 Pages 的 legacy 构建会把仓库根目录当成 **Jekyll 站点**，于是它读了 Hexo 的 `_config.yml`，看到 `theme: butterfly`，就去找一个同名的 Ruby gem——当然找不到。**Hexo 生成的 HTML 根本没被看到。**

## 关键坑二：本地部署会留下构建缓存

改成「本地 `hexo generate` → 推到 `gh-pages` 分支」之后能跑通了，但 `hexo-deployer-git` 会保留一个 `.deploy_git` 缓存目录，把上一次的内容一起带过去，导致源码文件污染 `gh-pages`，Jekyll 又报同样的错。

## 最终方案：让 GitHub Actions 在云端构建

把构建搬到 GitHub 的服务器上，本地只负责写和推：

```
main 分支（源码）
   ↓ push 触发
GitHub Actions：装 pnpm → 装依赖 → hexo generate
   ↓ 上传产物
GitHub Pages（发布 workflow 产物）
```

Pages 的发布源设成 **GitHub Actions**（而不是某个分支），于是完全绕开了 Jekyll。

日常写作只需要三步：

```bash
git add .
git commit -m "新文章"
git push
```

推完大约一分钟，线上自动更新。

## 本地预览

写的时候想在浏览器里看效果，跑：

```bash
pnpm exec hexo server
```

然后打开 http://localhost:4000 。注意预览会生成 `public/` 目录，它是构建产物、不纳入版本控制，之后 `git pull` 前先清掉，否则会挡住合并。

## 这个站点包含什么

- 顶部菜单：首页 / 归档 / 标签 / 分类 / 关于
- 本地搜索（`hexo-generator-searchdb` 生成索引，不需要第三方服务）
- 暗色模式、代码高亮、打字机副标题
- 源码在 [michalrees/michalrees.github.io](https://github.com/michalrees/michalrees.github.io)
